# 高热视频拆解协议

## 1. 先确认能看到什么

按可靠度使用：完整视频/字幕或逐字稿、关键帧、标题与文案、置顶/高赞评论、公开数据、作者体量。缺哪层就说明哪层不能判断，不从链接标题脑补画面。

## 2. 七层拆解

| 层 | 要回答的问题 |
|---|---|
| 钩子 | 前 1–3 秒/首屏如何让人停下？是结果、冲突、悬念、身份还是视觉异常？ |
| 情绪与问题 | 用户为什么在意？好奇、实用、认同、焦虑、幽默、惊奇还是争议？ |
| 视觉装置 | 有什么一眼可懂的画面规则、前后对比、镜头运动、角色或生成效果？ |
| 留存结构 | 如何持续制造信息缺口、升级、反转或阶段兑现？ |
| 最终兑现 | 结尾是否兑现标题/钩子？产物、结论、教程或情绪回报是什么？ |
| 分享/评论触发 | 为什么会转发给具体的人、收藏、模仿或留言？用评论证据验证。 |
| 分发变量 | 账号体量、投流、热门声音、事件窗口、IP知名度等非内容因素。 |

每层只写有用判断，不要把所有元素都夸一遍。

## 3. 反事实找真正驱动

对每个显眼元素问：拿掉它，内容还成立吗？

- 换掉热门音乐仍然成立：音乐可能只是辅助；
- 换成普通开头马上失效：钩子是驱动；
- 去掉最终效果只剩过程：结果展示是驱动；
- 普通账号复制大号内容未必有效：账号体量是干扰变量。

每条作品最后仅标 1–2 个 `DRIVER`，其余分为 `SUPPORTING / INCIDENTAL / CONFOUND`。

## 4. 从个案到规律

至少 3 条、2 个账号后再找共性：

- 哪种钩子重复出现；
- 哪种用户情绪或使用场景重复出现；
- 哪种视觉/叙事结构跨账号仍有效；
- 哪些只发生在大号或特定事件；
- 相似作品中失败或普通样本有什么差异。

只看成功者会产生幸存者偏差。找不到失败样本时，把“规律”表述为待验证假设。

## 5. 转译边界

可以复用：结构、节奏、用户冲突、视觉规则、互动机制。

不可直接复制：原脚本、原文案、连续镜头设计、角色形象、音乐/素材、独创梗和账号人设。输出需要说明“保留什么机制、换成什么业务内容、和原作有什么明显差异”。
